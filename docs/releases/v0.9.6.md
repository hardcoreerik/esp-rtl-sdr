# esp_rtl_sdr 0.9.6

## Fixes

Receiver recovery when a dongle disconnects during startup is the main fix in this release. An intermittent USB connection could let an old initialization attempt finish after disconnect cleanup and leave the receiver in FAULT, or interfere with a newly attached receiver. Disconnect cleanup now waits for the active start to unwind while USB events continue to be processed. A canceled start reports NO_DEVICE, and the next stable attachment can be opened normally. Cleanup uses nonblocking API-lock attempts so it can retry while USB processing continues. See [PR #69](https://github.com/hardcoreerik/esp-rtl-sdr/pull/69).

## Also included since the last GitHub release page, 0.9.4

- RTL2832U digital AGC support for E4000 receivers, including restoration of the requested state after initialization and before streaming, shipped in the 0.9.5 tag. See [PR #65](https://github.com/hardcoreerik/esp-rtl-sdr/pull/65).
- Blog V4, V4L, V3c, Nooelec SMArt V5 and E4000/XTR are implemented profiles. E4000 includes manual and tuner AUTO gain, opt-in hardware offset tuning and RTL digital AGC. The historical internal name `e4000_experimental` is retained. Per-model capabilities and valid tuning ranges apply.
- Refreshed receiver/API documentation, version markers and example image versions.

## Verification

The interrupted-start regression extracts actual driver functions and covers disconnect during initialization, disconnect before successful completion, replacement startup, genuine attached-device faults and API-lock contention. The original code failed the regression and the fix passed 32 checks. Focused session, uninstall, allocation and recovery checks passed. Release CI covers Linux/Windows host tests, version consistency and ESP32-P4 compilation on ESP-IDF 5.5.4 and 6.1.

COM39 Tab5 lab runs observed interrupted initialization settle to IDLE, automatic Nooelec V5 streaming, and a return swap to XTR streaming near 2.40 MS/s with zero reported driver overruns or drops. Those runs used the core fix plus a project-local SDK USB patch. The final nonblocking-lock refinement was covered by host tests and CI rather than a separate flash. Broad RF calibration, every receiver model and long-duration stability remain open.

## SDK and application boundary

The separate ESP-IDF USB host assertion fixes tested through OrcSDR are tracked in [OrcSDR PR #239](https://github.com/hardcoreerik/OrcSDR/pull/239) and require OrcSDR build integration. Installing driver 0.9.6 alone does not apply those SDK patches. An earlier watchdog reset remains unattributed. A loose USB connection was reported as fixture context.
